# Dive Plan text formatting

The Aim, Goals and Secondary objectives fields in Edit Dive Plan now have visual formatting controls. The same toolbar covers Conditions notes, safety/human-factor long text, emergency long text and Plan notes: 22 fields in total. Bold, italic, underline, bullet lists, numbered lists, clear formatting, undo and redo are available. Select text and use the toolbar, then Save plan. Standard keyboard formatting shortcuts work. Toolbars keep 44px targets, fit one compact desktop row and wrap on narrower screens; text boxes retain a 224px minimum writing area. Collapsible Plan sections retain their draft values.

Canonical strings and arrays remain plain text. An optional private `textFormatting` map stores restricted version1 JSON presentation metadata. No migration rewrites existing Plans. The visual editor only accepts paragraphs, text, hard breaks, lists and the three text marks; links, images, scripts and arbitrary HTML attributes are not stored or executed as formatting. Read and Save normalise the metadata to the 22 supported field keys and discard invalid documents. The complete merged Plan is checked once at Save against the existing 200000-character cloud limit after weather packing. If presentation alone prevents sync, formatting is omitted and the UI confirms that all entered text was retained. Canonical fields themselves are never truncated; existing oversized canonical records still use the normal local Save and cloud-review flow. Saved workbench rendering uses escaped React nodes and rejects metadata that no longer matches the canonical text. Metadata validation is bounded to 100000 characters, 10000 nodes and 16 nesting levels; if entered text exceeds those formatting bounds, all text is retained for normal Save as plain text and the field explains that fallback.

Formatting-only edits participate in normal unsaved-change detection. Spaces, blank lines and Unicode survive typing, Save, reopening, backup JSON and duplication. Plan notes retain their exact whitespace during formatted and plain-text Saves; existing records are never rewritten automatically. Immutable saved weather responses remain excluded from per-character edit comparisons and are still included in Save. Integration API and public-profile allowlists do not include the new private metadata or long-text fields. Derived Dive snapshots retain the complete original Plan, including presentation. Owner storage losslessly packs only the 22 supported canonical long-text fields, legacy objective aliases, validated presentation and saved weather; repeated Plan text, including synthesized objective and stop/abort narrative, is stored once with bounded references to the original text fields. Canonical IDs and references stay visible, all original bytes are restored behind the owner read boundary, and existing record-size limits remain unchanged. New version2 snapshots bind their full contents to the source event, original record hash and timestamp; the original Plan-record hash is also verified independently. Legacy version1 snapshots keep their original validation path. No calculation, permission, calendar, provider or owner-record changes are part of this feature.

Tiptap React/ProseMirror/StarterKit3.31.4 are pinned in both dependency locks. The npm lock also reconciles its previously stale root metadata and missing existing dependencies with the existing package manifest; those packages were already part of the pnpm build.
