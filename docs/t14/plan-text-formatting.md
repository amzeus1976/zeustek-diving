# Dive Plan text formatting

The Aim, Goals and Secondary objectives fields in Edit Dive Plan now have visual formatting controls. The same toolbar covers Conditions notes, safety/human-factor long text, emergency long text and Plan notes: 22 fields in total. Bold, italic, underline, bullet lists, numbered lists, clear formatting, undo and redo are available. Select text and use the toolbar, then Save plan. Standard keyboard formatting shortcuts work. Toolbars keep 44px targets, fit one compact desktop row and wrap on narrower screens; text boxes retain a 224px minimum writing area. Collapsible Plan sections retain their draft values.

Canonical strings and arrays remain plain text. An optional private `textFormatting` map stores restricted version1 JSON presentation metadata. No migration rewrites existing Plans. The visual editor only accepts paragraphs, text, hard breaks, lists and the three text marks; links, images, scripts and arbitrary HTML attributes are not stored or executed as formatting. Read and Save normalise the metadata to the 22 supported field keys and discard invalid documents. An empty metadata map retains exact visual-editor text when formatting falls back to plain text. Saved workbench rendering uses escaped React nodes and rejects metadata that no longer matches the canonical text. Metadata validation is bounded to 100000 characters, 10000 nodes and 16 nesting levels; if entered text exceeds those formatting bounds, all text is retained for normal Save as plain text and the field explains that fallback.

Formatting-only edits participate in normal unsaved-change detection. Spaces, blank lines and Unicode survive typing, Save, reopening, backup JSON and duplication. Formatted Plan notes retain their exact whitespace; untouched legacy notes keep the existing trim behaviour. Immutable saved weather responses remain excluded from per-character edit comparisons and are still included in Save. Integration API and public-profile allowlists do not include the new private metadata or long-text fields. No calculation, permission, calendar, provider or owner-record changes are part of this feature.

Tiptap React/ProseMirror/StarterKit3.31.4 are pinned in both dependency locks. The npm lock also reconciles its previously stale root metadata and missing existing dependencies with the existing package manifest; those packages were already part of the pnpm build.
